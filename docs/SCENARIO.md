## 한 줄

**나에게 해당하는 규칙 변화만, 바뀌기 전 → 바뀐 뒤로, 시행 전에 먼저 알려 준다.**
조회 서비스가 아니라 구독형 브리핑. 조회·전체 연혁은 국가법령정보센터 몫이고, 우리는 '걸러서 먼저 알려 주기'에 집중한다.

## 핵심 가치 (2026-10-23)

1. **쉬운 말로 풀어 주기** — 원문 개정이유·조문을 바뀌기 전 → 바뀐 뒤 한 쌍으로. 신뢰는 원문 발췌(글자 그대로)와 적용 시기(부칙)로 받친다.
2. **나와 관련된 것만** — 한 달 5천 건 중 내 조건에 닿는 몇십 건. 처음부터 정확할 수 없으니 관심 있음/없음 피드백으로 다듬는다.

수집·노이즈 필터·백필은 이 둘의 재료다. 잘못된 정보의 위험(적용 시기·조건 누락, 방향 오류, 놓침, 재개정)은 쉬운 말 v2의 검증 장치로 막는다 — ROADMAP '1. 품질'.

## 개인 흐름 (목업 1~6)

1. **상황 입력** — "어떤 상황이세요?"를 자유롭게 입력 (예: "화성 제부도에서 펜션을 운영하고, 숙박 앱으로 손님을 받아요"). 예시 문구 칩, '분야 직접 고르기' 대안.
2. **맞춤 프로필 확인** — AI가 입력을 **지역 · 하는 일 · 챙겨 볼 분야 · 지켜볼 법령**으로 바꿔 보여 주고, 사용자는 체크만 고친다.
   - 입력은 프롬프트, **저장은 구조화된 프로필** (`config/profiles.json`과 같은 모양). 알림 매칭은 매일 기계적으로 해야 하므로 프롬프트를 그대로 쓰지 않는다.
3. **내 타임라인** — 묶음: `곧 시행`(D-day) · `최근 바뀜` · `의견 받는 중`(입법예고). 각 항목 제목은 법령명이 아니라 **무엇이 바뀌는지 한 문장**.
4. **변경 상세** — 단계 막대(법률 공포 → 시행령 공포 → 시행), 무엇이 바뀌나(전→후), 나에게 해당하는 이유, 확인해 볼 것, 원문 링크. "자동 요약이니 원문 확인" 문구 고정.
5. **조항 변화 추적** — 법령 전체 연혁이 아니라 **내 관심 조항 하나**의 시점별 변화. 예: 교통·에너지·환경세법 시행령 제3조의2(유류세 탄력세율)는 2022년 이후 24번 개정 — 대부분 기한 연장, 2026.4.1 인하 폭 확대(휘발유 492 → 450원). 데이터: `lsJoHstInf`(조문별 변경 이력) + 판별 본문.
6. **알림 설정** — 받는 곳(텔레그램/이메일), 언제(그날 아침 · 매주 월요일 정리 · 시행 7일 전 · 입법예고 마감 전), 받게 될 메시지 미리보기.

> 핵심 루프는 알림이다. 앱 접속은 처음 설정과 상세 확인용.
> 흐름: 상황 입력 → 프로필 확인 → 최근 한 달 미리보기 → 바로 구독 → 이후엔 알림 → 눌러서 상세.

## B2B 보고서 (목업 7)

같은 엔진, 앞단만 다름. 구성: 해당 변경 수 · 검토 필요 · 가장 가까운 시행 → 변경 표(판정 · 법령 · 무엇이 바뀌나 · 시행) → **우리 사업장에 해당하나**(배출시설·인허가 데이터 매칭, 아이디어 #461) → 출처·면책.

## 질문으로 들어오는 경우 (B2C 유입)

질문은 유입 경로로만 쓴다. **답은 판정이 아니라 변화**로, 끝은 구독으로.

| 질문 유형 | 예 | 답하는 방식 |
|---|---|---|
| 변화 확인 | "일시적 2주택 비과세 바뀌었나요?" | 언제·무엇이 바뀌었나(전→후), 시행일, 원문 링크 → 이 조항 알림 받기 |
| 현행 규정 확인 | "지금 취득세 중과 기준이 뭐예요?" | 현행 조문 요약 + 원문 + 최근 변경 이력 |
| 개별 판정 | "제 경우 비과세 되나요?", "세금 얼마 나와요?" | **판정하지 않음.** 관련 변화·조문만 보여 주고 세무사 등 전문가 확인 안내 (나중에 전문가 연결) |
| 범위 밖 | 소송 전략, 신고 대행 | 정중히 안내만 |

- 질문마다 먼저 유형을 판별하고, 개별 판정 요청이면 위 원칙을 지킨다. 판별이 애매하면 판정 쪽으로 본다(보수적으로).
- 근거는 공포된 원문만. 답에 출처 링크가 없으면 내보내지 않는다.
- 세무사법·변호사법 경계는 서비스 공개 전 전문가 확인.
